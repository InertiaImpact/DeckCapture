# Implementation status

This repository contains a runnable Windows-first pilot, rather than only the original UI simulation. The implementation is intentionally explicit about the distinction between synthetic validation and station hardware acceptance.

| Area | Implemented | Remaining acceptance or expansion |
|---|---|---|
| Supervisor | Persistent SQLite jobs, per-channel workers, immutable configuration snapshots, revisions, idempotent HTTP commands, restart reconciliation, local space reservations | Long-duration station workload and power-loss exercises |
| Recording | Real FFV1 v3 / 10-bit 4:2:2 Matroska and 24-bit PCM; synthetic and FFmpeg DeckLink adapters; preset/custom duration, preparation, manual start/stop, extension, pre-roll | Actual DeckLink Duo/Duo 2 driver/build/format validation; exact trigger timing; native SDK adapter for trustworthy hardware lock/drop/format events |
| Content automation | Confirmed black-to-content transition, explicit prepared/armed monitoring expiry, hard duration; default-off black-and-silence end inference with grace and global kill switch | Hardware automation uses fresh analyzed content with explicit no-input reports blocking it; unknown hardware lock no longer prevents a start. Auto detection, deck timing and source-change behavior still require hardware acceptance |
| Browser | Compact channel rows, exact input assignment with row/endpoint highlighting, optional SDK card/connector metadata, verified model diagrams and persisted operator/custom wiring, graphical settings, input/format discovery, development diagnostics, capture controls, channel overview with per-channel live players and controls, automatic input monitoring and channel JPEG thumbnails, H.264/AAC live video with Listen/Mute for audio 1–2, independent audio 1–2 RMS meters, detected input format and recording-only counters, queue, QC views, reports, settings/import/export, per-field visibility, credential entry | Additional card/profile/connector and concurrent-input acceptance; desktop wrapper remains future UI work; current scopes and compressed previews are monitoring proxies |
| Delivery | Local-first queue, overnight/time-zone windows, concurrency and per-copy/aggregate limits, outside-window speed, per-file and 12-hour admission override, holds, verified-prefix resume, SHA-256 and atomic package publication | Production SMB server semantics, throughput, disconnects, identity and ACLs |

| Deployment | Framework-dependent or optional self-contained Windows publish for supervisor and worker, browser assets, optional paired media-tool bundle lookup, Windows Service hosting support | Service registration, signed installer, certificates, roles/SSO and production provisioning |
| Media lifecycle | Retains completed packages, spool and failure evidence; no silent overwrite or automatic deletion | Establish a reviewed retention/cleanup workflow after verified delivery; monitor capacity until then |

The application handles capture, QC and delivery. Archive cataloging and retrieval are outside its scope. Original proposed features remain in `DESIGN_AND_IMPLEMENTATION_PLAN.md`; a design statement is not evidence that a feature is implemented.

The compact channel editor preserves configured row order and exact FFmpeg input keys. Row clicks, field focus and endpoint selection highlight assignments without remapping; missing saved inputs remain visible. Five documented diagram templates cover original Duo/Quad, Duo 2/Quad 2 and 8K Pro, with an operator-defined custom fallback for other models. SDK automatic mapping requires exact handles, nonzero card groups and known SDI/profile evidence; operator wiring persists independently as an explicit annotation and cannot override SDK grouping or verified assignments; an unknown SDK layout may receive a strictly confined operator annotation while retaining its group ID. Legacy DeckLink SDI labels cannot identify a card model. Active/opening endpoints remain protected. Diagram coverage is not universal model recognition, measured signal lock or hardware capture acceptance; consult `operations/INPUTS.md` for the evidence matrix and limitations.

Windows input diagnostics now include optional bounded PCI node/parent/location evidence and raw SDK topology/interface attributes. A separate fixed idle-only PCI identity command may bind DirectShow filters for identity getters without a graph, streams or settings changes; ordinary discovery never binds them. PCI metadata and probe results do not enable new grouping or remapping. The target idle probe matched all ten SDK endpoints to Windows PCI nodes: six legacy endpoints by exact TopologicalId and four Duo 2 endpoints by PersistentId. The legacy endpoints occupy three separate two-endpoint PCI branches (one reports slot 4; the other slot labels are unknown); the four Duo 2 endpoints share one PCI node reporting slot 2. This is successful diagnostic correlation, not enabled automatic PCI-based UI grouping or accepted legacy jack order. See `operations/INPUTS.md` for the observed evidence and explicit limits.

## Upstream references

The workflow draws inspiration from [vrecord](https://github.com/amiaopensource/vrecord) and [QCTools](https://github.com/bavc/qctools). DeckCapture does not vendor their application code. [FFmpeg's DeckLink device documentation](https://ffmpeg.org/ffmpeg-devices.html#decklink) describes the external adapter's build and input options. FFmpeg, FFprobe, the Blackmagic driver/SDK and optional upstream QC applications are separate dependencies; this repository does not redistribute their binaries or grant their licenses.
