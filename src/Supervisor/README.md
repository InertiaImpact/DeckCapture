# Supervisor

Read `../../AGENTS.md`, `../../docs/architecture/CONTRACTS.md`, and `../../docs/architecture/MAINTENANCE.md` before changing this component.

`Program.cs` owns HTTP binding, authentication, same-origin commands, idempotency and route wiring. `CaptureSupervisor.cs` owns recording transitions and worker lifetime. Its `Control` partial owns settings, transfer admission, reports and operator commands. `StateStore` owns SQLite transactions and request receipts. `NotificationService` owns the independent durable SMTP outbox. `OfflineQcService` analyzes completed media read-only. `wwwroot` contains the actual dependency-free browser client.

Every mutable recording/delivery collection and state transition belongs under the supervisor state gate. Take snapshots there, then release it before device, media or network I/O. Track pending input opens/commands through shutdown. A browser disconnect must not cancel an accepted recording command. The worker completion result is authoritative; a missing stop acknowledgement does not override a successful completion event.

`PrepareRecordingRequest.StartImmediately` combines preparation and the existing revisioned Start into one accepted command. Reject it together with WaitForContent before creating a job. Once preparation has been accepted, browser cancellation cannot cancel the start gate; keep the worker acknowledgement and existing Failed/evidence behavior authoritative when Begin is uncertain. `DefaultDurationMinutes` is an optional configuration preference: null retains the first preset in existing order, and an explicit value must belong to DurationPresetsMinutes. It does not change durations in immutable prepared job snapshots.

`CaptureSupervisor.AutomaticMonitoring.cs` schedules monitoring from the hosted tick, never from GET requests or browser playback. It serializes automatic opens, staggers attempts by at least one second, and uses monotonic per-channel retry deadlines (15 seconds for input failure, 30 seconds when capture capability is unavailable). Automatic sessions force the monitoring timeout to zero and create no RecordingJobs or filenames. Preserve the exact source ownership checks: prepared, opening, recording and finalizing jobs always take precedence. Explicit no-input reports persisting 15 seconds can retire an automatic monitor for retry; unknown lock and unavailable analysis alone must not restart an input.

Configuration changes cancel/drain affected idle monitors outside the state gate before the scheduler uses their replacements. Recording settings remain immutable snapshots. Maintenance reserves admission before draining idle monitors, and rejects prepared/active recordings rather than closing them. Keep automatic attempts paused through that drain and the lease; shutdown cancels pending opens and awaits cleanup. The compatibility monitor-stop command only closes an idle monitor, so the scheduler can resume it later. Lifecycle tests in `SupervisorAutomaticMonitoringTests.cs` use a fake clock and fake inputs; they do not establish hardware reconnect or multi-channel throughput acceptance.

Do not add a route that opens arbitrary files or runs arbitrary commands. Keep approved-root confinement, source/destination non-overlap, reparse checks, schema validation, authentication and secret exclusion intact. SQLite is the operational authority; sealed package sidecars are capture-time snapshots and do not change when an operator later releases QC review.

Build the project from the repository root. The build and publish targets copy the complete worker runtime into `capture-worker`; keep this behavior when changing output layout.

`InputWiringRules` validates physical-diagram annotations and guards annotations used by active/opening inputs. `GET /api/inputs/catalog` serves the static evidence-backed model catalog independently of driver readiness. The discovery partial clones both capture settings and operator wiring under the state gate, then performs bounded observation and display-only projection outside it. Browser drafts may preview wiring, but only normal validated configuration saves persist it; preview authority rules must match `Capture/InputWiring.cs`.

Live preview routes authorize the exact current channel/job ownership and only generated HLS asset names. They must not expose arbitrary spool files or follow links. The browser player owns only playback: pause/mute/close/channel switches never stop workers. Session-specific media URLs and retained media nodes prevent stale-session playback and SSE flicker.

Monitor errors retain their full sanitized cause in the API and logs. The browser uses `monitoringFailureMessage` for short preview failure messages; channel tiles use concise signal status. Do not paste driver stderr into those controls or infer a disconnected cable from a missing signal.

The capture Overview renders existing channel sessions only. Keep each card's command target independent of the selected detail channel, and retain media/control nodes across live updates. Player cleanup is client-only and must never call recording or monitor stop. Preview audio arbitration follows native video volume controls so at most one channel is audible. Auxiliary audio buttons and their obsolete actions are removed from both views; native volumechange handlers and cleanup remain essential.

Detail capture markup places Recording setup in the main column after preview and metrics. `updateCaptureMarkup` reconciles both columns while retaining the setup, channel list and preview nodes. Keep that DOM order declarative; relocating the live video during each refresh can interrupt playback, and replacing the setup can lose typing/focus. A changed setup key still deliberately rebuilds controls for another channel or recording state.

The main column uses CSS grid for a compact preview and adjacent quick metrics, followed by full-width setup and detailed metrics/scopes. `metricItems` supplies both readouts so measurements and freshness rules remain consistent. Keep the preview a direct child of the main column: the reconciler retains that node rather than recreating its player on live refreshes.

The browser feature modules and their maintenance guide live in `wwwroot`; read `wwwroot/README.md` before changing them. Detail and overview share one player controller and a separate image controller. Keep session/token ownership, local cleanup, paused playback, native audio arbitration and stable setup/media nodes covered through direct module imports and a real browser check. Channel status belongs in the tile; do not restore a second status row or manual-monitor browser controls for automatic monitoring.

In `wwwroot/app.js`, `renderOverview` owns stable keyed cards, `updateOverviewCard` patches their status/actions, and `attachOverviewPlayer`/`stopOverviewPreview` own per-channel playback. Session/token keys and `isLivePreviewMediaUrl` keep authorization scoped to generated media. `overviewActions` must handle Prepared/Recording job states before its RecordingJob-owner fallback; that owner is normal for active capture. Overview commands validate the card's channel, job ID and revision before posting. See `tests/capture-overview.test.mjs` for target/revision regression cases and the implementation status for browser acceptance.

Automatic monitoring belongs to the hosted supervisor, not browser rendering. The automatic-monitoring partial staggers input opens and uses monotonic retry deadlines; failed/unavailable devices must never spin in a tight loop. Keep capture timers independent of slow device opens. Admission, config retirement, maintenance drain and shutdown share the supervisor ownership gate. Prepare/recording owners exclude automatic attempts, and only idle monitor sessions may be retired on input loss. Maintenance reserves before draining monitors so an automatic retry cannot reopen an input during an update.

Background QC runs after successful capture-session disposal. OwnsInputUnderGate protects physical input admission; IsActive still covers durable validation work for maintenance, reports and shutdown. Keep completion addressed to the exact old job, not its channel. QcProgressSnapshot persists observed stages without changing command revisions; never infer a passing file from percent complete. Restart recovery still requires review of retained media. Ownership regression coverage is in SupervisorValidationOwnershipTests; see docs/operations/QC.md.
