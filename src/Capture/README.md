# Capture

See `../../docs/operations/CAPTURE.md` for adapter behavior, media/timing limitations and hardware acceptance. `CaptureBackend` launches a single isolated worker for each input. `CaptureWorkerHost` and `SpoolCapture` own the FFmpeg input and retained one-second segments. `SegmentMonitor` samples closed segments for preview/metrics without reopening the device. `MediaProcess` uses separate arguments and Windows job containment. `MediaValidation` validates the final FFV1/PCM file.

Never substitute simulated success for missing hardware capabilities. Device lock and hardware drop events are unavailable in this FFmpeg adapter. Keep monitoring proxies labeled accurately. Keep original segments and partial output on failure; never retry into an existing recording filename. Stop requests may arrive during automatic finalization: await the authoritative completion event rather than requiring another command acknowledgement.

`MediaValidation` explicitly sets video slice-decoder threads to `Math.Clamp(Environment.ProcessorCount / 4, 1, 8)`, independently of the preservation encoder budget. FFprobe otherwise inherits the codec's single-thread default, which made the retained 1080p59.94 FFV1 scan too slow for its finalization budget. Keep the entire `-count_frames` scan and all codec/container/audio/positive-count checks: packet counts, frame skipping or short read intervals are not equivalent validation. `MediaValidationTests` verifies the bounded arguments and an actual full decode against deliberately misleading frame-count metadata.

Explicit monitor-only opens carry `CaptureOpenOptions.MonitorOnly`; normal prepared recording opens must leave it false. Automatic monitoring forces unlimited duration. Explicit compatibility monitor API opens use the optional `MonitoringTimeoutMinutes` (0 disables expiry), while prepared/content-wait sessions use `MaximumArmedMinutes`. Once recording output begins neither pre-recording timeout applies. Keep the distinction in the worker policy and supervisor snapshots; never implement an unlimited monitor by increasing or disabling the prepared-job limit globally.

The worker executable project is `../CaptureWorker`. Tests under `CaptureTests.cs` include real synthetic encoding when `DECKCAPTURE_CAPTURE_INTEGRATION=1`. Use the repository test script, retain failure evidence, and record hardware validation separately.

`RecordingFrames` and `RecordingMediaSeconds` are nullable until the worker accepts Begin, then report deltas from the cumulative FFmpeg progress at that point. They exclude retained pre-roll and have the same sampled-progress granularity (about one second); they are not frame-accurate trigger or final-file counts. Keep cumulative `Frames`/`MediaSeconds`, dropped-frame/integrity evidence and original timestamps unchanged. Finalization still derives authoritative duration/frame totals from the preserved file. `DetectedVideoFormat` reports dimensions, rational frame rate and field order only when known from the original closed master stream, using the existing bounded per-worker metadata probe; proxy HLS/JPEG dimensions and configured Auto/manual codes are not detection. Explicit no-input or dead input suppresses that public observation. Reading closed segments never opens the DeckLink input again.

`CaptureWorkerLifecycle` keeps input readiness separate from final capture completion. A final worker result received before readiness must fail the pending open immediately with its bounded, redacted cause. A later process exit must not replace that result. Process shutdown must drain stdout/stderr even when the child already exited, before disposing diagnostic writers; otherwise fast startup failures can disappear from `encoder.log`. `CaptureWorkerStartupTests` covers the protocol ordering, sanitized fallback and an actual child-process drain race.

Record the FFmpeg exit code even after an operator/duration stop: decimal and hexadecimal values in `encoder.log`/failure results, and the raw value in `timing.json`. A native crash can follow fully written segments while stderr contains only an unrelated warning. Any nonzero exit, or an unexpected zero exit before a stop request, retains failure and original spool; never accept it as a complete master based on the last warning or a valid final segment. `EncoderExitTests` covers this distinction. A November 4 hardware run recorded Windows access violation `0xC0000005` during shutdown with `MSVCP140.dll_unloaded`; the native shutdown cause remains unresolved and synthetic shutdown success does not close that hardware acceptance gap.

## Input identity and inventory maintenance

`InputDiscovery.cs` owns bounded FFmpeg source/format parsing. Exact `name` remains the saved and runtime identifier; descriptive text is display-only. `DeckLinkInventory.cs` optionally enriches those endpoints by an exact SDK device-handle join. It groups only nonzero DeviceGroupIDs, preserves 64-bit IDs as hexadecimal strings, and leaves missing/ambiguous attributes null. Refresh never writes configuration or assigns channels.

Native helper source and its public build recipe live under `native`. The optional Windows binary is deployed at the supervisor release's `media-tools/DeckCapture.DeviceInventory.exe`. Normal discovery reads iterator, profile attributes, connection configuration and bounded read-only Windows PCI facts; it never binds DirectShow filters or enables inputs. Keep profile activation and configuration-set calls out of all diagnostic modes. The receiving workstation needs Desktop Video; SDK headers/compiler are build dependencies only. The helper has a separate five-second deadline after FFmpeg's 20-second discovery bound; failure preserves the FFmpeg inventory with `inventoryError`.

`DeckLinkModelCatalog.cs` owns five vendor-documented diagram templates (original Duo/Quad, Duo 2/Quad 2, 8K Pro), their direction metadata and known SDK profile maps. `InputWiring.cs` overlays explicitly saved operator/custom diagrams only where no SDK grouping conflicts; it never edits capture keys or raw inventory. `connection.connectorIds` supports profile-assigned multi-BNC inputs; the singular inventory field is retained only for Duo 2 compatibility. See `docs/operations/INPUTS.md` for the source/coverage matrix and `CONTRACTS.md` for response/configuration shapes.

A layout is not automatic endpoint identification. Legacy Duo/Quad may both enumerate as DeckLink SDI; do not infer the original model, physical card grouping or connector from a label, opaque handle, index order or zero ID. Unknown models can use explicit custom input/output/reference connectors, labeled as operator assertions. SDK group evidence takes precedence; a single operator layout can augment an unknown SDK group only when all present bindings agree on that group and no SDK layout/connector assignment exists. Mixed groups are refused, the effective SDK ID is retained, stale annotations remain visible, and active endpoint wiring changes are rejected. New verified model/profile rules require primary vendor diagram/table evidence and hardware acceptance, not similarity to an existing model. Do not confuse Duo/Quad 2 `2dhd`/`1dfd` profiles with 8K Pro profile IDs, or hardware subdevice count with profile-group size. The diagram does not prove current link mode or signal lock.

Regression checks must cover missing helper/driver, malformed and duplicate handles, zero IDs, unknown model/profile/connection, discovery reordering, exact-name save/restart, and active assignment rejection. Synthetic/fake inventory tests are not hardware acceptance. Any new connector rule requires SDK/manual evidence and validation on that card/profile before it can produce a physical assignment.

## PCI identity diagnostics

`WindowsPciInventory.cs` validates optional native SetupAPI/Configuration Manager facts. `topologicalId` and `deviceInterface` retain exact SDK attributes separately. No rule decodes SDK IDs/handles into Windows PCI addresses, groups legacy endpoints by parent/container, or invents unavailable slot labels. PCI errors are optional failures, not FFmpeg/source failures.

The fixed `DeckLinkPciCorrelation.ProbeIdleAsync` path invokes native `--pcie-correlate-idle` only through the supervisor's explicit idle-reserved POST command. Filter binding may access hardware, so do not reuse it for ordinary GET discovery or bypass the shared preparation/format reservation. The exact registered interface may be a virtual child: resolve only through bounded parents to the first PCI ancestor, require Blackmagic there and refuse foreign PCI/cyclic/truncated paths. Raw interface ancestry is retained separately from the resulting PCI ID. Identity getters need no graph, pins, streams or setters; unsupported/ambiguous joins remain diagnostic results. Grouping is disabled regardless of the probe outcome until a separately reviewed policy has evidence and regression coverage. See the API and operations input guide for response fields, target observations and acceptance limits.

Target verification on November 3, 2026 matched all ten SDK endpoints to Windows PCI nodes (six legacy TopologicalId matches and four Duo 2 PersistentId matches). The operations input guide records exact handles, three legacy branches and optional slot evidence. This is an observed identity correlation; automatic PCI-based UI grouping remains disabled and legacy connector order is not inferred. Preserve that boundary when extending policy or tests.

Keep hardware lock, input-presence reports, analyzed media and drop counters separate. DeckLink lock is nullable; owned FFmpeg frame-flag messages can report input loss/recovery without a second capture open. Analysis freshness is monotonic and bounded; protocol receipt age also matters. Auto format omits format_code rather than passing an invented FourCC, and only promises initial detection. Read-only inventory SDK status getters preserve HRESULT/null on unsupported devices and never enable or start a second input.

Never hard-code the encoder thread budget outside CaptureProfile.encoderThreads. An input-buffer overrun is actual FFmpeg packet discard, and CFR output duplication can mask the lost video timing. Preserve passthrough timestamps and sticky integrity observations independently of monitoring success and progress drop counters. Missing audio samples are unavailable analysis, not synthetic silence. Review late stderr events before releasing final media.

Live A/V monitoring is a second encoded output from the existing input, never a second SDI open. Keep all lossy conversion and rolling deletion confined to the disposable HLS directory. Test the exact MF/AAC/HLS/FIFO feature set before opening real hardware and retain the JPEG fallback when unavailable. Preview muxer recovery must not change preservation output or fabricate successful live playback. The shared process remains a fatal-codec-failure boundary; capture errors retain the master evidence.

`SegmentMonitor` is instantiated once per owned worker. Its bounded, cached FFprobe observation identifies the actual source audio channel count; an additional 250 ms raw PCM sample measures the first two original channels without downmixing. The old mono sample remains the independent aggregate used by content detection. `AudioChannelRmsDbfs` is empty for unavailable channel metadata, one value for mono, and two for stereo/multichannel. Keep the 512 KiB read guard and finite -100 dBFS silence floor. Never fill unavailable meters with aggregate levels or synthetic silence. `AudioChannelMeterTests` covers unequal stereo, mono, malformed interleaving, missing probing and per-worker caching using the paired media tools.
